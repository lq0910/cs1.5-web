# CS 1.5 Web — 浏览器单机 FPS 练习项目

浏览器里运行的 CS 1.5 风格单机 FPS：GoldSrc 风格移动、BSP/WAD 地图加载、武器和手雷、4v4 BOT 回合制、C4 安装与拆除。

本项目仅供个人学习研究、自玩娱乐使用，不作商业用途。Counter-Strike 名称及原版地图、模型、音效等素材的权利归各自权利人所有。本仓库不包含原版游戏素材，也不提供原版安装包；请自行确认素材来源和使用许可。

当前支持选择 CT/T 阵营。默认地图为 `de_dust2`（需自行准备地图素材），每队 4 人；玩家与 BOT 共用回合、武器和 C4 规则。原版“72街仓库”地图名为 `cs_assault`；项目另有一张自制的 `white_house` 双层房屋移动测试地图，两者不是同一张图。

---

## 快速开始

```bash
cd cs15-web
pnpm install          # 首次
pnpm make-bsp         # 把内置 white_house 移动测试地图编译成 BSP + WAD（首次或改了地图后跑）
pnpm dev              # 打开终端显示的本地地址
```

仓库不附带原版素材。要加载原版地图、模型与音效，请先将你合法持有的 CS 1.5 安装文件放在本机，再按下文“原版地图”一节运行提取工具。未准备原版素材时，可运行 `pnpm make-bsp` 后用 `?map=white_house` 体验内置移动测试地图。

> **Node 版本注意**：用 nvm 装的 Node（v18 以上，推荐 v20/v22）即可。
> 若 `pnpm dev` 报 `Cannot find module ...rolldown-binding...node`，说明该 Node 开了
> hardened runtime 且与原生模块签名不一致，换一个 Node 即可（例如 `nvm use 22`）。

| 命令 | 作用 |
|---|---|
| `pnpm dev` | 开发服务器（热更新） |
| `pnpm build` | 类型检查 + 生产构建到 `dist/` |
| `pnpm test` | 无头测试（物理、几何、BSP/WAD、武器弹道、购买快捷键、手雷落地爆炸、回合与完整 4v4 对局） |
| `pnpm typecheck` | 只做类型检查 |
| `pnpm make-bsp` | 把内置移动测试地图编译成 `public/cstrike/maps/white_house.bsp` + `white_house.wad` |
| `pnpm list-maps -- "<cstrike目录>"` | 列出本地 CS 安装里的地图与 WAD |

| 武器 | 伤害 | 护甲穿透 | 射速 | 弹匣 | 相对极速 | 参考价 |
|---|---|---|---|---|---|---|
| AK-47 | 36 | 0.775 | 600 RPM | 30 | 221 u/s | 2500 |
| M4A1 | 32 | 0.70 | 666 RPM | 30 | 230 u/s | 3100 |
| AWP | 115 | 0.98 | 41 RPM | 10 | 210 u/s | 4750 |
| 沙鹰 | 54 | 0.90 | 200 RPM | 7 | 230 u/s | 650 |
| USP .45 | 34 | 0.50 | 400 RPM | 12 | 250 u/s | 500 |
| Glock 18 | 25 | 0.50 | 400 RPM | 20 | 250 u/s | 400 |
| MP5 Navy | 26 | 0.60 | 750 RPM | 30 | 250 u/s | 1500 |
| 刀 | 15 / 65(捅) | — | — | ∞ | 250 u/s | 0 |

手感的实现方式（都在 `src/game/weapons.ts` / `combat.ts`，可被无头测试逐条验证）：

- **精度锥**：静止 0.28° → 移动 5.6° → 空中 12°（AK），蹲下再乘 0.68；按下暂停后的第一枪额外收紧到 0.45 倍——这就是"点射准、扫射飘"的来源。准星间隙实时跟随这个锥角，**准星不会骗你**。
- **后坐力**是 GoldSrc 那套 **punch angle**：每发按弹道表把视角往上顶（AK 前 3 发几乎垂直上跳，第 4~9 发右偏，第 10 发后向左拉回），同时缓慢回正（7°/秒）。子弹方向 = 视角 + punch + 锥内随机散布，所以**不压枪就会打高**——实测 12 连发 punch 从 -2.8° 累积到 -11.5°，1170 单位处弹着点从 57 爬到 238 单位高度。
- **伤害**：`伤害 × 距离衰减(每 500 单位) × 命中部位倍率(头 4× / 胸 1× / 腹 1.25× / 腿 0.75×)`，再套 CS 的护甲公式（护甲吸收一部分并自身消耗，护甲不足时余量直接透传）。
- **枪声/脚步/击中音效及队员无线电语音**可从本机 CS 1.5 安装文件提取到 `public/cstrike/sound/`，连发时带轻微随机音高，远处按距离衰减。
- **视觉反馈**：第一人称枪口焰跟随枪管，BOT 枪口焰从第三人称模型枪口发出；墙上有弹孔贴花和命中灰尘，视图模型保留后坐、摆动和换弹动作。

## 4v4 BOT 与回合制（M3）

打开 http://127.0.0.1:5173/?map=de_dust2 ，点进游戏后：

- **可选择 CT 或 T**，两队各 4 人；BOT 有独立战绩与经济。
- **回合流程**：热身 → 冻结时间（5 秒，可按 <kbd>B</kbd> 买枪）→ 进行中（默认 3 分钟）→ 结算 5 秒 → 下一回合，先到 16 胜。
- **胜负条件**：全歼对手 / 炸弹爆炸（T 胜）/ 炸弹拆除（CT 胜）/ 时间到（CT 胜）；**下包后计时切到 35 秒引信**，CT 普通拆包 10 秒，购买拆弹器后 5 秒。
- **C4 操作**：持包 T 到 A/B 包点按 `5` 取出 C4，站稳并按住左键约 3 秒装包；CT 靠近已装 C4 按住 `E` 拆包。松开或离开范围会中断进度；持包者阵亡时 C4 掉落，T 队友触碰后拾取。
- **经济**：初始 $800，击杀 +$300，胜方 $3250，败方 $1400 起（连败加成），下包/拆包 +$300
- **买枪菜单**（<kbd>B</kbd> 后按 1-6）：护甲+头盔、AK/M4、AWP、沙鹰、拆弹器
- 高爆手雷最高 100 基础伤害，在 350 单位内按距离衰减，墙体会遮挡爆炸伤害。C4 引爆时产生范围伤害、火光、烟尘和闪光。
- HUD 保留雷达、顶部计时、击杀信息、生命、护甲、金钱与弹药；双方战绩按住 Tab 查看。

**BOT 怎么想事**（`src/game/bots.ts` + `src/game/match.ts`）：

- **导航图是自动生成的**（`src/game/nav.ts`）：按 64 单位网格扫描全图，向下逐段探测**每一层可行走地面**（能识别地道和二层），再用"站立 hull 扫掠 + 中点可站立"判定连通，A* 寻路。
- BOT 和玩家跑**完全相同的物理与武器代码**（`pmPlayerMove` + `CombatSystem`），不能作弊，只是打得不如人。
- 有**视野**（100° 半角 + 视线遮挡 + 3200 单位上限）、**反应时间**（0.12~0.32 秒，随难度变化）、**转身速度上限**、**瞄准误差会随时间收敛**、**点射纪律**（步枪打 0.2~0.5 秒短点射而不是一梭子）、**听声辨位**（听到枪声会去查看）、**卡住检测**（顶墙时会侧移+跳）。
- **命中判定用 4 个判定盒**（头/胸/腹/腿），伤害走 CS 的护甲公式：实测 **AK 爆头能穿透头盔一枪致死**，而穿甲弹（护甲）能挡下胸部射击。
- 队伍目标每回合定一次：T 全队护送带包的人去选定的包点，CT 分守两个点，下包后改扑炸弹——这条改动把之前 CT 6-0 的一边倒变成了 **4-4 均势**（三个随机种子测出来都是 4-4，场均 4~6 次下包、有爆炸也有拆包）。

### 三角形绕序（地图"到处是洞"的元凶）

GoldSrc 的面绕序与 OpenGL/three.js 期望的**相反**：按平面法线校验，Valve 的地图有 **82~90%** 的面是反的（dust2 3489/4002）。three.js 默认背面剔除，于是这些面直接消失，露出黑色虚空——表现就是"地面和半截墙都没了"。

现在构建几何时按**面所属平面的法线**（含 `side` 修正）校正绕序，缺少的面全部回来。我自己生成的图是 0%（写出的就是 OpenGL 约定），所以这个 bug 只在真图上暴露。

| 地图 | 面数 | 需翻转 |
| --- | --- | --- |
| de_dust2 | 4002 | 3489 (87%) |
| cs_office | 8390 | 7021 (84%) |
| de_inferno | 6746 | 5731 (85%) |
| cs_747 | 7365 | 6547 (89%) |
| cs_estate | 4504 | 4039 (90%) |
| white_house（自产） | 318 | 0 (0%) |

### BOT 卡住/原地跳的修复（重要）

`findPath` 在**目标不可达**时返回 `null`（有些地图的导航图是碎的），而 BOT 之前会**无视这一情况继续朝目标直线走** → 顶墙 → 触发卡住检测 → 每 2.5 秒跳一次。现在：

- 没有路线时改为**就近巡逻**（在可达区域内随机选点），不再朝不可达目标硬走；
- **接近目标 200 单位即视为到达并驻守**（CT 守点就该站着）；
- **先转向再前进**（朝向偏差 > 75° 时原地转身，不推墙）；
- 路径点 **3 秒未到达就跳过**，连续跳过 3 个则重新寻路；
- 卡住时**先侧移绕行**，1.2 秒后才允许跳一次，且跳跃冷却 2.5 秒。

实测（dust2，3 个种子 × 6 局）：原地跳 **9~15 → 0~0.5 次/BOT/回合**，移动速度 **0.5~1.0 → 2.6~2.7 单位/tick**，击杀 **6~11 → 16~21**。

## 画面调参（对比原版时用）

光照图按 GoldSrc 的方式处理：Valve 的地图是**每 luxel 3 字节 RGB**，引擎把它当**乘数**（固定管线 gamma 空间相乘），并且有 Quake 系的 **overbright ×2**。这两点缺一个，真图就会黑得看不见（我前后踩了两次）。想微调可以直接改 URL：

| 参数 | 含义 | 建议 |
| --- | --- | --- |
| `?lmi=2` | 光照图倍率（默认 2） | 调大整体更亮 |
| `?lm=1.6` | 光照图 gamma（默认 1） | **调大主要提亮暗部**，室内会明显变亮 |
| `?debug=1` | 显示物理/渲染调试信息 | 平时不用 |
| `?skill=0.9` | BOT 强度 0~1 | 默认 0.55 |

例如 `?map=de_dust2&lm=1.6` 会把阴影里的 luxel 32 从 64 提到 108。

## 内置移动测试地图

原版“72街仓库”对应 `cs_assault`，使用从原版素材转换的地图文件。项目内的 `white_house` 则是独立制作的移动测试地图，不是 `cs_assault`，也不是原版地图。运行 `pnpm make-bsp` 会把它编译成真正的 BSP v30 文件（约 105 KB、318 面、331 叶子、1163 clipnode），其中两张贴图**故意放到 WAD 里**，走的是和原版 dust2 一样的"BSP 引用 → WAD 查表"路径。地图本身是移动实验室：

- 长直道 → 地面加速 / 极速 · 薄长墙 → `PM_SlideMove` 贴墙滑行
- 4 级 16 单位台阶 → `PM_StepSlideMove` 自动上台阶（stepsize 18）
- 16 单位矮台 vs 24 单位高台 → 台阶高度上限 · 32/64 单位箱子 → 45 单位跳跃
- 40 单位高矮通道 → 站立 72 高过不去，蹲下 36 高能过 · 空场 → 连跳

## 架构

```
src/
  engine/
    math.ts                 向量数学（纯函数，Z-up 坐标系）
    input.ts                键鼠 + 指针锁定，产出 GoldSrc 风格 UserCmd
    collision/
      types.ts              Hull(站立/蹲/大物体) 与碰撞世界接口
      clip.ts               PM_ClipVelocity
      brush.ts              凸体碰撞：Minkowski 展开 + 线段裁剪
    bsp/
      types.ts              BSP v30 结构与字节尺寸
      reader.ts             完整 lump 解析（边界全检查）
      miptex.ts             miptex 解码（BSP 与 WAD 共用）
      wad.ts                WAD3 解析与按名查表
      tree.ts               BSP 树构建器（AABB 区域递归切分，保证是合法划分树）
      write.ts              BSP v30 / WAD3 序列化器（地图编译器）
      collision.ts          clipnode 递归 hull 检测（SV_RecursiveHullCheck）
      geometry.ts           BSP → Three.js 几何 + 调色板贴图 + 光照图图集
    render/
      boxGeometry.ts        盒子 → 三角形（世界坐标 UV，Z-up→Y-up）
      textures.ts           程序化贴图（占位素材）
      renderer.ts           Three.js 场景、光照、雾、相机
  game/
    constants.ts            HL1 SDK / CS 1.5 原始常量（重力 800、跳 268.328…）
    movement.ts             pm_shared.c 的移植：PM_PlayerMove 全流程
    player.ts               本地玩家：移动状态 + 视角 + 蹲下视角过渡
    map/
      build.ts              地图数据结构 + 挖门窗洞 / 生成楼梯的工具
      whitehouse.ts         内置白房子
      loader.ts             BSP/WAD 加载（含出生点落地修正、缺失回退）
  ui/hud.ts                 调试 HUD
tests/                      34 个用例：physics / render / bsp
tools/                      list-maps.mjs、make-bsp.mjs
```

设计要点：

1. **物理与渲染解耦**。模拟跑在 GoldSrc 的 Z-up 坐标里，常量照抄原版；只有 `boxGeometry.ts` / `renderer.ts` 在边界转成 Three 的 Y-up。
2. **固定 64 tick 模拟 + 不限帧渲染**，为将来加联机留接口。
3. **碰撞后端可替换**。移动代码只依赖 `CollisionWorld`，`BrushWorld`（手写地图）与 `BspCollisionWorld`（原版 clipnode）互换；测试里做了**逐帧差分**，两者轨迹必须一致。
4. **常量不"优化"**。`movement.ts` 保留 `PM_*` 命名与 HL1 SDK 写法，方便对着 C 源码排查手感。
5. **光照图**。GoldSrc 每面烘焙光照（16 单位一个 luxel，8 位灰度），打进图集后用 `MeshBasicMaterial.lightMap`（UV 通道 `uv1`）渲染——世界只由烘焙光照照亮，和原版一致。

## 素材说明

本机使用的 CS 1.5 素材位于 `public/cstrike/` 与 `cs1.5/`，两者已被 `.gitignore` 排除，不应提交或再分发。浏览器版 BOT 使用项目自己的寻路与状态机，不依赖原版 Win32 BOT DLL。

## 已知限制

- **导航图在部分地图上还不够连通**（de_dust2 约 84% 可达且两个包点都通；de_inferno / cs_747 碎片化较严重，BOT 会困在局部区域打转）。建议先玩 de_dust2。
- BOT 不会用手雷/闪光弹，拆包时也不会先清场。
- 光照图图集用简单 shelf packing，超大原版地图可能需要调大图集尺寸或分块。
- 没有 VIS/PVS 剔除（原版用 BSP 可见性数据做遮挡剔除），大图帧率会受影响。
- 原版素材由使用者自行准备；缺少对应地图、模型或音效时，相关内容无法完整显示。

## Dust2 机器人与 LED 资讯屏（2026-10-09）

简单难度仍然降低反应、命中率和伤害，进攻、寻路与装包执行不因难度降低而停留在出生区。导航按小步验证坡道和连续楼梯的累计爬升，每回合选择可达包点，持包队员进入装包区域后持续安装 C4。冻结时间不推进机器人任务，枪声不会反复重置包点路线，守包位置每回合固定分配。

Dust2 靠近警家一侧的 GAMEHELPER 横幅墙安装实体 LED 屏，显示新闻标题轮播、来源、发布时间、同步时间和横向滚动快讯。每条新闻展示 12 秒，每 5 分钟从 IT之家科技 RSS 和 MIT 人工智能 RSS 获取更新，保留原文语言；断网标记缓存或离线并重试，不填充虚构新闻。

`npm run dev` 与 `npm run preview` 均提供 `/api/tech-news`。资讯需要服务器联网；只把 `dist/` 放到纯静态服务器时，需要另外提供该同源接口或反向代理到运行此接口的服务。RSS 聚合实现位于 `server/techNews.ts`，屏幕实现位于 `src/engine/render/newsScreen.ts`。

机器人设计参考：[Michael Booth 的官方 Counter-Strike Bot GDC 讲解](https://media.gdcvault.com/gdc04/slides/making_of_official.pdf)。此项目继续使用自身 TypeScript 状态机与玩家移动物理。
